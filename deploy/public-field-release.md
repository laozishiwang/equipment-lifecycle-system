# 扫码免登录发布准备

后端候选 `/opt/equipment-public-backend-candidate.6H0XAD` 包含 `backend.jar`、`backend-source.tar.gz` 和 `028_public_field.sql`，使用目录内 `sha256sum -c SHA256SUMS` 验证。前端候选须单独确认已通过同一联调并记录哈希。

发布前保存可恢复的数据库及照片备份，检查备份清单和当前运行镜像的回滚标签；核对 028 的三个新增列、索引及 `ems_field_guest` 用户当前状态。该 SQL 不可直接重复执行；MySQL DDL 自动提交，部分执行失败时应先检查实际状态，再只补缺失步骤。新增列与索引使用显式在线算法和 5 秒元数据锁等待；如不支持或等待超时，应停止检查，不要强制复制表。

确认旧程序可兼容新增列后应用 028；再部署经过验证的前后端候选，保持现有生产数据库、上传卷、Druid 环境文件和监控覆盖配置。使用公网 IP 作为 HTTPS 主机名检查首页、验证码和现场入口，并以真实手机完成扫码；不要在生产创建测试工单。

若软件发布失败，使用发布前镜像回滚标签恢复前后端，保留 028 增量列、现场账号及新写入的姓名和记录，不通过删除表或回滚数据库丢弃真实业务数据。原有二维码设备 ID 可以继续使用；由于系统直接公网可访问，任何获取链接的人均可提交，工人姓名为自填，不是身份认证。
