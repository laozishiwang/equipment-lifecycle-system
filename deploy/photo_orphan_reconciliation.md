# 私有照片疑似孤儿核对流程

本流程默认只读，不能把审计报告直接作为删除依据。审计分别读取数据库和文件系统，并非原子快照；上传进程可能已经写文件但尚未提交引用。禁止在线自动删除，也禁止仅根据文件年龄删除。

1. 执行 `python3 deploy/photo_storage_audit.py --project equipment-live --compose-file compose.production.yaml --env-file .env.production`，保存完整报告和执行时间。退出码 1 表示有待核对项，2 表示审计失败；失败不得继续处理。
2. 对疑似孤儿先保留至少 24 小时；对报告中的缺失引用、磁盘告警或异常文件名分别排查，不能混作孤儿清理。检查附件备份可读取、数据库与附件恢复演练已完成，并确认备份时间覆盖目标文件。
3. 安排维护窗口，停止全部可能写入或删除私有照片的后端实例与定时清理任务，等待正在执行的请求和事务结束。保持 MySQL 和文件卷可访问，确认没有其他实例或外部程序写入该卷；无法确认时停止。
4. 在维护窗口通过只读检查逐个复核：文件名符合应用格式、仍为普通文件且未发生替换，修改时间超过宽限期，工单照片、巡检照片和暂存照片三个表均无同名引用。数据库不可用、记录不完整、文件异常、时间不可信或任一检查不确定时，保留该文件。
5. 当前项目未提供生产删除命令：将核对结果及备份位置交由运维审查，在有恢复方案的维护窗口内按厂区既定操作流程处理。禁止直接对报告中的候选批量执行 `rm`；本流程也不自动移动或删除文件。
6. 维护结束后启动服务，重跑只读审计和照片上传、查看回归；记录处理人、时间、备份位置和复核结果。数据库和文件备份不是原子快照，不能据此保证恢复任意并发写入。

隔离验证：在专用开发环境执行 `python3 deploy/photo_storage_audit_integration_test.py`，脚本构造合成旧孤儿，验证其被报告且文件未被审计删除；不得将该测试指向生产环境。
