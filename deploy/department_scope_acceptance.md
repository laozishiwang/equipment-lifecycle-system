# 部门数据范围验收清单（尚未实现）

设备部门归属表仅记录归属，不会自动约束设备业务 JDBC 查询。启用部门隔离前，必须在隔离数据库中创建至少两个部门、各部门设备、工人、主任以及跨部门维修员；所有验证均通过实际接口，而不是只检查菜单或前端隐藏。

## 业务策略

实施前需将以下规则写成明确的后端策略并统一适用于读写：上级部门是否包含下级部门、未归属设备的处理、跨部门扫码报修和巡检、维修员待接单池与已分配工单、主任的查看范围、部门变更后的历史记录与附件可见性。若依角色数据范围的多角色合并、管理员与停用部门也需有明确处理。不能仅靠页面筛选或注解推断安全边界。

以下为可供实现的默认方案，**尚未启用**：管理员全厂；部门主任看其部门及下级设备；工人查看本部门及下级设备、本人提交的巡检与报修；维修员跨部门可见待接单池及分配给自己的工单，完成后仍可访问本人参与的记录；工单及照片按工单权限控制。多角色取授权范围并集。设备无部门时，在启用隔离前由主任批量分配；迁移期间保留现有访问，界面明确显示未归属数量，不能称为已隔离。正式启用时未归属设备仅管理员可管理，已有本人报修和被分派维修保留访问以免阻断闭环。历史按当前设备归属及本人参与权限决定，设备调动后保留审计；不自动追溯授予旧部门全量权限。部署前必须用实际组织和测试账号验证这些默认选择。

## 统计口径（拟定，待验收）

主任工作台、费用和故障排行及其下钻、导出统一按设备当前归属部门计算；本人历史报修或维修参与权限仅用于访问工单及其照片、费用详情，不单独把其他部门的设备计入部门统计。设备调部门后，历史费用与故障随当前归属进入新部门统计；全厂管理员查看全部设备。此规则避免个人参与例外扩大部门总额，启用前仍需覆盖跨部门参与、设备调动以及下钻与导出一致性测试。

## 控制器覆盖矩阵

| 控制器与入口 | 当前约束 | 建议增加的后端范围 |
| --- | --- | --- |
| `EquipmentController`：列表、详情、历史、新建、创建可选部门、编辑、二维码基础地址 | 菜单权限；列表与详情未按部门限制 | 设备列表、详情、历史及编辑按设备归属；创建与分配应限制可管理部门；二维码基础地址不暴露设备内容 |
| `EquipmentDepartmentController`：部门列表、归属读取与修改、批量分配 | 设备编辑权限；保存归属及历史 | 限制可管理部门和目标设备；批量操作全部成功或回滚；未归属仅授权管理者分配 |
| `InspectionTemplateController`：设备模板读取与配置 | 设备及模板相关权限 | 通过设备归属验证读取与修改；扫码人员仅能读其授权设备模板 |
| `InspectionController`：列表、详情项目、快照、创建、转单、关联工单 | 本人巡检或 `inspection:viewAll`；转单要求报修权限 | 巡检创建检查设备范围；列表、项目、快照和转单统一结合部门及本人例外；关联工单再执行工单范围 |
| `InspectionPhotoController`：暂存、移除、上传、列表、单文件 | 上传者或巡检查看权；暂存与设备关联 | 每个入口分别检查设备或巡检范围；单文件 ID 不能绕过范围；未绑定暂存仅上传者可操作 |
| `WorkOrderController`：列表、详情、报修、撤回、取消、接单、到场、完工、试运行、关单、转派、费用、维修人员列表 | 报修人、维修人、待接单及 `order:viewAll` 等权限 | 保留跨部门待接单和本人参与例外；管理操作结合部门及派工范围；费用与详情范围一致；不能仅保护列表 |
| `WorkOrderPhotoController`：上传、列表、单文件 | 报修人、维修人、待接单与全厂权限 | 统一沿用工单读取及上传策略；转派前后、取消及关闭状态分别回归 |
| `MaintenanceController`：计划列表、到期汇总、增改停用、完成、记录 | 对应菜单和操作权限，无部门过滤 | 列表、汇总与计划 ID 操作按设备范围过滤；维修员可在明确派工范围内完成；未归属计划按迁移策略处理 |
| `EquipmentOverviewController`：总览、费用、费用下钻及导出、故障排行及导出 | `order:viewAll` | 限制为授权设备范围，统计、明细、导出采用同一条件；避免全厂汇总泄露其他部门金额 |
| `FaultCodeController`：故障代码目录 | 目录相关权限 | 作为全厂共享基础字典，不包含设备或人员敏感数据；保持目录权限，不误套设备范围 |
| `InspectionStageCleanup`、`PrivatePhotoStorage`：后台清理和容量 | 系统内部任务 | 清理与配额不以用户数据范围过滤；仅内部调用，避免将系统任务权限直接暴露为用户接口 |

## 必测接口

- 设备列表、单条详情、历史、编辑、部门配置与批量配置；通过直接 ID 访问另一部门设备，不仅测试列表。
- 设备二维码现场读取、巡检模板、巡检提交、巡检列表、项目、模板快照、历史工单与事后转报修。
- 巡检照片暂存、删除、绑定、列表及单文件下载；使用其他部门的照片 ID 单独探测。
- 工单列表、详情、报修、接单、到场、维修、试运行、关单、撤回、取消、转派及费用；测试跨部门维修交接与状态变化。
- 工单照片上传、列表及单文件下载；测试待接单、已转派和已关闭的边界。
- 保养计划列表、提醒汇总、新建、编辑、停用、完成和记录；核对列表、统计与直接 ID 操作一致。
- 工作台概况、费用汇总和下钻、Excel 导出、故障排行和下钻、设备历史；统计、导出不应包含当前账号范围之外的数据。
- 设备归属变更、未归属设备、无部门账号、停用部门、多个角色、管理员、并发转派和分页游标；验证搜索和筛选不会扩大范围。

## 验收标准

对每个接口执行允许和拒绝案例；拒绝访问时不返回目标记录内容、照片或敏感金额。数据变更测试检查数据库没有写入，照片测试包括猜测文件 ID 的下载请求。保养汇总与列表、费用汇总与导出在同一权限范围内互相核对。所有核心扫码、报修、接单、维修、试运行和关单流程在约定的跨部门策略下完成。未覆盖全部入口或未完成真实角色测试时，不得将部门隔离标记为完成。

## 可执行回归方案

在独立 Compose 项目和独立测试库运行，禁止以正式地址或正式数据库作为目标。初始化部门 A、A1（A 的下级）、B；设备 EA、EA1、EB、EU（未归属）；账号工人 WA/WB、主任 DA/DB、维修员 T、管理员 ADMIN，以及同时具备 A、B 角色的 MULTI。每个账号通过真实登录获取独立令牌。建立不同故障文本、照片字节、费用金额和到期计划作为可区分的夹具。

1. 设备表与单条接口：WA 允许 EA、EA1，拒绝 EB；DA 允许 EA、EA1，拒绝 EB；DB 拒绝 EA；MULTI 允许 A 与 B；ADMIN 允许所有设备。逐一测试详情、搜索、分页、设备历史与二维码对应的现场接口，不能仅核对数量。
2. 工人报修与巡检：WA 对允许的设备创建巡检和报修；对 EB、EU（正式隔离策略）尝试创建时断言拒绝，并检查巡检、工单、日志、暂存和照片数量未增加。WB 无法通过 WA 的巡检或照片 ID 读取明细；WA 本人报修在设备调动后仍可查看。
3. 跨部门维修：WA 提交的待接单由 T 读取并接单，T 在工单分配后读取详情和照片、到场、登记分项费用、试运行；DA 在授权范围关单。将另一工单转派给 T，验证转派前后权限及照片下载；WB 不因猜中工单和照片 ID 获得访问。
4. 主任报表：分别为 EA、EB 写入不相同的人工与配件费用及故障代码；DA 的总览、按日期费用、下钻、Excel 和故障统计只包含 A 范围，DB 仅包含 B，ADMIN 为二者合计；无权限角色直接请求导出应拒绝。检查含取消工单、返修、未关联历史费用时现有统计口径不变。
5. 保养：各设备建立不同到期状态计划；核对 DA、DB 列表、筛选、游标、到期汇总与记录一致；对范围外计划直接执行完成、编辑和停用均拒绝且无数据库变更。验证 T 的可操作范围与已确定的维修分派策略一致。
6. 边界与并发：断言禁用部门、无部门用户、多个角色及管理员不扩大未授权范围；并发调整归属与写巡检／派工时，验证事务结果遵守明确的生效时点；权限变更后重新请求列表、详情、附件、统计及导出，防止缓存或旧游标绕过。

先对现有版本运行拒绝案例作为基线，记录预期失败；逐控制器改造后重复相同测试，最后运行现有扫码、报修、维修、费用、巡检及保养回归。正式部署前备份并演练回滚，先仅审计范围和未归属设备数量，再在隔离环境完整通过所有矩阵后实施统一开关，不能分批上线一个会产生绕过的安全边界。

## 最小完整接入顺序（接口清单可执行）

运行 `python deploy/department_endpoint_inventory.py` 列出当前 58 个业务路由；控制器或路由数量变化将返回非零并提示重新审查。该脚本基于注解做静态盘点，不能识别同数量的路由替换、动态映射，也不能证明接口受保护。

1. 使用当前认证用户 ID 从 `sys_user`、`sys_user_role`、`sys_role`、`sys_role_menu`、`sys_menu` 查询该操作对应的启用角色；从 `sys_role_dept` 和启用的 `sys_dept` 构建可信自定义范围与下级范围。不能直接信任客户端传入的部门或角色集合。验证用户、角色、部门被停用后的立即生效行为，明确登录缓存带来的权限撤销时延。
2. 建立统一设备、工单、巡检授权查询片段，参数化部门和用户 ID；列表在 `LIMIT` 前过滤，单条、附件及写入使用同一授权规则。工单的本人参与和 `REPORTED` 待接单例外与设备授权分开；不以全厂查看菜单权限绕过部门条件。无归属设备迁移与本人历史例外按上文执行。
3. 所有直接更新在事务内锁定与验证设备归属后写入；部门变更使用一致的锁顺序，并测试权限检查与变更并发，避免检查后归属变化。批量分配必须先核查所有对象和目标部门，任何失败整体回滚。
4. 费用、故障、设备总览、导出与保养到期统计分别沿 `cost -> order -> equipment`、`repair -> order -> equipment`、`plan -> equipment` 关联同一范围；不得从全厂聚合后在前端隐藏。设备履历内的工单和巡检需要分别使用各自权限，不能仅检查设备访问。
5. 联合部署所有入口的保护；在隔离库执行上面的正反例和旧闭环回归，确认未归属设备及真实角色数据已迁移后，再统一启用。部署前备份并准备回退，不允许将单一控制器成功视为部门隔离完成。
